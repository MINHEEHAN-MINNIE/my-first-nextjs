# 새 프로젝트 시작 순서

> Next.js 프로젝트를 만들어서 배포까지 가는 전체 흐름
> 2026-07-27 Day 1 독립 실행으로 검증

---

## 준비

| # | 명령 / 동작 | 뜻 |
|---|---|---|
| 1 | 프로젝트 폴더 생성 | Claude Code에게 구조와 파일 생성 요청 |
| 2 | `cd ~/프로젝트명` | 터미널을 그 폴더에 세운다 (`~`는 홈 폴더) |
| 3 | `pwd` | 지금 어디 서 있는지 확인 |
| 4 | `ls` | 이 폴더에 뭐가 들었는지 확인 |

**팁** — 경로 치기 귀찮으면 `cd ` 까지 치고 Finder에서 폴더를 터미널로 드래그.

## 로컬에서 띄우기

| # | 명령 | 뜻 |
|---|---|---|
| 5 | `npm install` | 필요한 패키지 **설치**. **프로젝트당 한 번** |
| 6 | `npm run dev` | 개발 서버 **실행**. 이 터미널은 이제 잠긴다 |
| 7 | 브라우저에서 확인 | `200` = 정상, `404` = 그 주소에 `page.js` 없음 |
| 8 | `Cmd + T` → `cd` | 새 탭 열고 폴더 다시 잡기 |

**주의**
- `npm install`의 "처음 한 번"은 컴퓨터당이 아니라 **프로젝트당**이다. 새 프로젝트마다 다시 해야 한다.
- `npm install`은 재료를 **사 오는** 일. 내 코드를 배포용으로 **묶는** 패키징은 Vercel이 나중에 한다. 방향이 반대다.
- 터미널 탭은 **두 개**를 쓴다. 하나는 서버용(건드리지 않음), 하나는 명령어용.

## git으로 기록하기

| # | 명령 | 뜻 |
|---|---|---|
| 9 | `git init` | 이 폴더를 git이 관리하게 한다 |
| 10 | `git add .` | 올릴 파일을 상자에 **담는다** |
| 11 | `git commit -m "메시지"` | 메시지 붙여 **봉인한다** |

**주의** — `-m`을 빼면 Vim 편집기가 열린다. 나오려면 `i` → 입력 → `Esc` → `:wq`. `:qa`로 나가면 메시지가 비어서 **커밋이 취소된다.**

## GitHub에 올리기

| # | 명령 / 동작 | 뜻 |
|---|---|---|
| 12 | GitHub에서 **저장소(repository)** 생성 | GitHub은 "저장소", Vercel은 "프로젝트". 용어가 다르다 |
| 13 | `git remote add origin <URL>` | 어느 창고로 보낼지 등록. **프로젝트당 한 번** |
| 14 | `git push -u origin main` | 첫 전송. 이후로는 `git push`만 |
| 15 | GitHub 새로고침 | 파일이 올라갔는지 눈으로 확인 |

**반드시 확인** — 저장소 만들 때 `Add a README file`, `Add .gitignore`, `Choose a license` **세 개 전부 체크 해제.** 하나라도 켜면 양쪽에 서로 다른 히스토리가 생겨 push가 거부된다.

**인증** — 새 컴퓨터에서는 `gh auth login`이 먼저 필요하다. (`GitHub.com` → `HTTPS` → `Y` → `Login with a web browser`)

## 배포

| # | 동작 |
|---|---|
| 16 | Vercel → Add New → **Project** |
| 17 | 저장소가 안 보이면 GitHub 앱 권한에서 해당 저장소 추가 (Private일 때) |
| 18 | **Import** → 설정 건드리지 말고 **Deploy** |
| 19 | 나온 주소를 휴대폰으로도 열어본다 |

## 이후 반복

```bash
git add .
git commit -m "무엇을 왜 바꿨는지"
git push
```

push하면 Vercel이 자동으로 다시 배포한다. 1분쯤 뒤 주소를 새로고침하면 반영된다.

---

# 절대 안 바뀌는 것 하나

**담기 → 봉인 → 보내기**

```
git add .   →   git commit -m "..."   →   git push
```

순서를 바꾸면 실패한다. 커밋 없이 push하면 `src refspec main does not match any` 에러가 난다.
브랜치는 **커밋이 하나라도 있어야 태어나기** 때문이다.

9~11번과 12~13번은 서로 순서를 바꿔도 되지만, 위 세 개만은 고정이다.

# 막혔을 때

1. **`git status`부터 친다.** 다음에 뭘 하라고 괄호 안에 적혀 있다.
2. **에러 메시지는 콜론 앞부터 읽는다.** 거기 적힌 게 누가 실패했는지다.
3. **"뭐가 틀렸지?"가 아니라 "뭐가 없지?"를 먼저 묻는다.**
4. 같은 문제로 15분 넘어가면 방식을 바꾼다.

자세한 건 `docs/errors.md` 참고.
